# Architecture as ontology. Invariants over ceremony.

架构首先说明系统中“什么东西是什么”，其次才是进程与目录。界面上的每个值和动作都应能追溯到同一组对象及规则。

## 核心对象

- **空间**：校区、建筑、楼层、房间。回答“在哪里”。室内示意图与室外米制坐标分别保留；没有测量依据就不做虚假的坐标对齐。
- **电路**：父子供电关系与计量边界。回答“电从哪里来，哪些表测到了同一份电”。空间包含关系不等于配电关系。
- **设备**：稳定身份、能力、负载类型与安全约束。产品显示名可以变，身份和历史不能随品牌替换而变。
- **绑定**：设备在一段时间内对应哪个空间和电路。搬动设备是增加一段历史，不是重写昨天的用电归属。
- **观测**：设备、启动纪元、序列号、观测时间、接收时间、单位、质量、来源。观测晚到与重复到达是正常情况，不产生第二份事实。
- **计划**：排课、维护和策略约束。计划有人使用不等于实际有人，缺少排课不等于空置。
- **命令**：有目标、有效期、序列号、权限和结果的意图。消息送达不等于输出改变；输出改变需关联回读验证。
- **核算与预测**：从观测导出的结果。保留时间范围、覆盖率、因子版本和模型评估；不能反过来冒充观测。

## 最短闭环

设备测量 → 边缘持久化与去重 → 平台入库 → 带质量的状态/核算 → 策略评估 → 授权调度 → 设备本地约束检查 → 执行与回读 → 平台确认结果。

边缘 SQLite 提交后才能确认已收到设备事件；平台 PostgreSQL 提交后边缘才能推进同步游标。重试采用稳定事件身份，避免网络恢复后重复记账。浏览器只访问同源 HTTP API，不直接接数据库或 MQTT。

策略先评估、再批准、再显式调度。调度时重新检查权限、时效、能力和负载约束，避免把早前通过的评估当成永久许可。失败、超时、拒绝和结果不确定分别保留，不用一个绿色成功提示掩盖差别。

## 必须始终成立的规则

1. 缺测、过期与未知值不是零，也不是安全证据。
2. SIMULATED、REPLAYED、REAL 来源在存储、展示、预测和导出中保留。
3. 同一时段不能把父级总表和它覆盖的下级表相加。
4. 能量以累计 Wh 的有效差分计算；跨启动、计数回退和不可确认区间不被自动补齐。
5. 用电量、费用、排放分别计算。碳因子/电价带有效期与来源；绝对排放不等于减排收益。
6. 用户校区权限同时约束列表、单项 ID、导出、历史报告和实时事件。
7. 设备执行安全约束位于设备端；云端算法不能取消本地保护。
8. 空间创作只在地图仓库；设备原生线协议由对应硬件仓库实现；跨产品统一能力与事件契约只在平台 `packages/iot-contract` 定义。生成副本按版本和哈希引用，不形成第二个可编辑主源。

这些规则由类型、数据库约束、状态转换和针对性测试承担。无需为每个业务名词增加一个微服务或一层通用框架。

## 运行结构

React/TypeScript 前端经 nginx 访问 FastAPI；API 与 worker 共享 PostgreSQL 中的持久状态，职责通过 Python 模块划分。控制、模拟和分析是同一后端镜像的独立运行角色：重建与训练不会占用控制循环。HTTP 读取预测快照或提交去重的内部计算任务，界面明确显示排队、运行、失败、过期和就绪；请求寿命不再代表任务寿命。预测输出保留基线比较与不确定性。

公共 Edge 连接设备协议和平台 API，负责可靠传输，并在明确的授权和有效期内运行有限现场规则；不重复实现全校核算、预测和调度。开发环境提供全校模拟设备；物理调度需独立部署开关、放行名单、设备级调试记录与正常运行约束共同成立，默认均不放行。

空间发布采用轻量全校 GLB、按建筑资源和独立房间示意图。网页按稳定 ID 关联模型与业务，不用模型名称猜测设备归属，也不把完整 Blender 创作工程塞进首次页面加载。

## 开发取舍

- 先形成可测试的完整模块化系统，再依据实际瓶颈拆分服务。
- PostgreSQL 为部署数据库；SQLite 仅用于明确的开发/测试路径及独立边缘队列。
- 生产与开发 Compose 分开，生产禁止测试身份、自动样例导入和物理控制默认开启。
- 数据量、延迟、恢复能力和浏览器表现依据实际测试记录判断；架构图不是验收记录。
- 校园现场、实物电路和真实节能需要各自的实测。缺少实测不阻止软件设计，但限制相应结论。

## 实现中进一步收敛的地方

- 设备本地保护以 C 实现为主源；原 Python 副本的有效测试迁入后移除，避免两个保护规则各自演化
- 边缘保留身份校验、可靠接收、转发与执行传输；全校预测、核算与编排集中在平台，不再重复三套算法
- 后端定义核心响应契约并生成 OpenAPI，前端从同一契约生成类型；观测计数、空值与命令序列的意义不靠两端各自猜测
- 原始遥测是事实源；小时投影是可以重建的派生数据，带时间、绑定、来源、质量和接收时点修订。修订不能倒灌到更早的预测评估
- 预测结果是有输入版本与授权范围的计算产物。后台计算、前台读取，不把每次打开页面都当成重新训练的理由
- 全校先加载轻量空间包，再按需加载作者建筑外观或产品模型；网页展示网格不会变成新的 CAD、PCB 或 Blender 创作主源

这些变化减少重复主源和重复计算。具体运行效果以对应版本的测试及性能记录为准。


## 五仓库统一升级的设计基准

2026-10-01：下述部分是本轮实现的共同约束；具体完成和验证状态以可执行测试与交付记录为准，不以架构文本代替实现。

### 产品和责任

- Campus 是全校业务与长期事实的中心，可部署在校内服务器，并不要求公网云。
- Edge 是可独立部署的现场软件进程，可使用既有 Linux 网关；无线适配需要实际相应接口。边缘不是第二套校园业务平台。
- Sense 采集人体存在等环境证据。当前主修订选择 5 V 低压有线供电和真实厂商 I2C presence 应用接口，以满足持续感知需求；不把原纽扣电池脉冲工作窗口误当连续雷达。
- Switch 面向固定普通照明的多通道控制。三路输出是三个独立通道，合计电表并不等于三路电表。
- Plug 面向经过负载核定的插接电器。计量、通断、输出带电反馈、局部温度保护各有独立含义，不是人体感知，也不是通用空调设温接口。
- njupt-map 只发布空间和显示资产；动态占用、用电和命令状态从业务接口按时间叠加，不写回几何源。

用户端设备卡片根据能力渲染。没有设温、调光、反馈或某种测量能力的设备，不出现冒充可用的操作或观测。

### 统一对象的最小增量

现有 Space、Device、Binding、Telemetry 和 Command 保持唯一身份及历史。增加：

1. Channel：一个设备内有独立能力与观测语义的端点；控制目标为 device_id + channel_id。
2. ChannelObservation：不可变观测，含启动纪元、序列号、observed_at、received_at、有效期、质量、来源和当时生效的空间绑定。未校准 raw 光照不能命名为 lux；局部板温不能命名为室温。
3. RoomMode：自动、人工保持、维护等有生效时间与到期时间的控制模式。保护/故障状态不能由远程模式覆盖。
4. RoomPolicy/Evaluation：版本化规则与一次冻结评估。重新下发必须复核当前模式、鲜度、权限及设备能力。
5. AnomalyEpisode：同一条件持续异常的一个事件，保留首末时间、阈值、基线、证据覆盖率和处理结果；重复扫描不产生重复告警。

空间层级回答“在哪里”；电路层级回答“哪些计量互相包含”；设备通道回答“谁能做什么”。三者不可用名称猜测或互相替代。

### 两个查询切面共用一套事实

固定教室查询时间区间得到时间轴；固定时刻查询全部授权教室得到空间快照。两者从同一历史状态重建函数派生，保持时刻、房间、质量和来源一致。

- 使用观测时间，而不是最新值或收到时间倒填过去。
- 每条观测只在其有效区间内支持状态；中断、坏质量、未完成绑定和过期区间为未知。
- 计划、期望输出、下发命令与独立观测分层展示。
- 多传感器的占用融合必须明确规则和覆盖范围；“任一有人”可形成有人证据，“无人”需要所要求的感知点全部新鲜且可用；缺失不投票为无人。
- 回路/设备功率分项不与包含它们的总表重复求和。状态时间占比有有效覆盖率分母说明。

### 基线、异常和调度

动态基线只使用目标时间之前、质量合格、来源明确的历史；按可获得的日历/课表条件分组，报告样本不足、离散程度和覆盖率。不存在的天气或占用输入不能宣称已经参与模型。固定上限、相对偏离、持续时间和解除回差各有明确作用。数据问题和用电异常分开呈现。

调度使用这些分析结果，但不会从异常直接跳过授权变成物理断电。保护优先；人工保持、维护、关键负载、动作间隔及设备资格在实际执行路径复核。终端始终拥有本地保护与拒绝权。

### 云边端断网语义

设备先本地执行获准的按键动作，再上报带序列的本地事件。Edge 持久保存消息和有效计划，模式改变使冲突自动计划失效。云端保存长期事实和跨房间策略。恢复连接先同步事实、人工模式与版本，再制定新动作，不补发已经过期或结果不确定的旧命令。

互斥控制责任与计划版本防止云和 Edge 同时争抢输出。传输确认只说明消息交付，实际结果必须来自相应设备回执/观测。没有独立反馈的灯控输出保留“执行器已报告”的证据等级，不能提升为“灯已亮”。

### 全校覆盖与交付准则

系统按授权空间目录遍历所有校区和房间，同一代码处理单教室与全校分布；开发数据和故障场景明确标为 SIMULATED。真实部署起始为空，不把仿真设备当作已安装设备。

软件完成需要源代码、迁移、启动部署、契约互通和关键异常路径测试；硬件设计交付需要原生电路/结构及相符接口。软件闭环、可编译固件和数字模型均不替代实物标定、RF/热/绝缘/EMC或现场投运。
